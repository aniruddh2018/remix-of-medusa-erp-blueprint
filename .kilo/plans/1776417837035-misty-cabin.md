# Plan: Implement Counter Sales Page with UX Similar to Main Sales Order Flow

## Overview
The user wants to implement a dedicated counter sales page with UX similar to the main sales order flow (billing tab in Sales.tsx). This will create a full-page version of counter sales, retaining efficiency but adding comprehensive features like invoice numbers, charges, notes, and optional customer details.

## Step 1: Design the Counter Sales Page
- Decide on structure: Dedicated page at /counter-sales, reusing components from Sales.tsx but streamlined.
- Key features: Full billing form (customer, invoice, items, charges, totals), but optional customer (default to "Counter Sale"), auto-focus on product search, no history tab.
- Include multi-customer slots for busy counters, but keep it optional/toggleable.
- Maintain keyboard shortcuts and focus management.

## Step 2: Create the CounterSales.tsx Component
- Create src/pages/CounterSales.tsx, adapting code from Sales.tsx billing tab.
- Reuse shared components: SalesItemsTable, BillingTotals, DrugBrandSearch, etc.
- Implement state for cart, customer, invoice, charges, notes.
- Add logic for optional customer, multi-slots (up to 9), scheduled drugs.
- Integrate with hooks: useDraftSave, useInvoiceSettings, useEnterNavigation.

## Step 3: Integrate Business Logic
- Reuse sales creation mutation from Sales.tsx.
- Handle FIFO inventory, GST calculations, unique invoice numbers.
- Support scheduled drugs with prescription prompts.
- Add auto-print on completion.

## Step 4: Add Routing and Navigation
- Add route for /counter-sales in src/App.tsx.
- Update sidebar (AppSidebar.tsx) to include link (e.g., Alt+3).
- Ensure focus recovery and module context.

## Step 5: Polish UX and Test
- Ensure keyboard navigation, real-time updates, error handling.
- Test integration with existing sales history.
- Run lint and typecheck commands to verify.

## Verification
- Simulate user flows: Product search → add to cart → complete sale.
- Check for edge cases: No customer, multi-slots, scheduled drugs.

## Timeline
- Step 1: 30 mins (design)
- Step 2: 90 mins (coding component)
- Step 3: 45 mins (logic integration)
- Step 4: 30 mins (routing)
- Step 5: 45 mins (testing and polish)

## Risks and Assumptions
- Reuses existing components; assumes no breaking changes.
- Customer optional; uses "Counter Sale" default.
- Multi-slots similar to existing dialog.
