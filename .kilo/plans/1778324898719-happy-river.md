# Plan: Migrate AI Gateway from Lovable to Fireworks

## Goal
Replace the Lovable AI gateway (`https://ai.gateway.lovable.dev`) with the Fireworks AI gateway across all Supabase edge functions.

## Context
The project currently has **4 edge functions** that call the Lovable AI gateway:
1. `supabase/functions/nl-query/index.ts`
2. `supabase/functions/ai-assistant/index.ts`
3. `supabase/functions/scan-invoice/index.ts`
4. `supabase/functions/parse-order-text/index.ts`

Each function currently uses:
- `Deno.env.get("LOVABLE_API_KEY")`
- Gateway URL: `https://ai.gateway.lovable.dev/v1/chat/completions`
- Model: `google/gemini-2.5-flash`

## Proposed Changes

### 1. Edge Functions (4 files)

In each of the 4 edge functions, update:

| Current | New |
|---------|-----|
| `LOVABLE_API_KEY` | `FIREWORKS_API_KEY` |
| `https://ai.gateway.lovable.dev/v1/chat/completions` | `https://api.fireworks.ai/inference/v1/chat/completions` |
| `google/gemini-2.5-flash` | `accounts/fireworks/models/llama-v3p1-70b-instruct` (or user-specified model) |
| `Authorization: Bearer ${LOVABLE_API_KEY}` | `Authorization: Bearer ${FIREWORKS_API_KEY}` |

The request body format is **OpenAI-compatible**, so `messages`, `tools`, `tool_choice`, and `model` should work as-is. Fireworks supports tool/function calling natively.

### 2. Supabase Secrets

After code changes, the edge functions must be redeployed with the new secret:

```bash
supabase secrets set FIREWORKS_API_KEY=fw_xxxxxx
supabase secrets delete LOVABLE_API_KEY  # optional cleanup
supabase functions deploy
```

Update any references in:
